# The Dashboard

The Dashboard is the DM's command center during a live session. It assembles prepared material and current campaign context without replacing deeper Archive content.

## Core jobs

- Start a prepared session and immediately see what matters.
- Keep the current scene and participants in focus.
- Open an NPC, location, clue, reminder, or note with minimal navigation.
- Track lightweight session state and unresolved threads.
- Capture an unexpected name, ruling, or event without leaving the session.
- Launch a prepared or improvised encounter in The Battlefield.

## Candidate first-release layout

- **Session header:** title, in-world date, real-world date, and status.
- **Current focus:** active scene, location, objective, and read-aloud material.
- **Cast:** relevant player characters and NPC summaries.
- **Threads:** active goals, clues, secrets, and likely next scenes.
- **Scratchpad:** rapid notes and prompts.
- **Quick access:** pinned Archive pages and encounter launch actions.

The layout remains a design question. A prototype should be tested at typical laptop and tablet sizes with realistic campaign data.

## Interaction principles

- Preserve the DM's place when opening supporting detail.
- Prefer keyboard shortcuts for frequent actions while keeping actions discoverable.
- Make private versus player-visible state unmistakable.
- Allow improvised content to be captured first and organized later.
- Avoid notifications or animations that compete for attention.

## Open design concerns

- Is one active scene enough, or must multiple scenes remain staged?
- Which state persists automatically when a session ends?
- How should real-time player sharing work, if at all?
- Which data must remain available during a network interruption?
